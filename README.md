# ICT Construction Estimator

2026년 정보통신공사 표준품셈 전체 587쪽의 본문·표·해설·원문 이미지와 제공된 빈내역 양식을 연결한 정적 웹앱입니다. 13개 장의 번호 항목 822개, 추출 표 726개, 계산 후보 4,032개를 수록합니다. 후보의 원문 대조와 조건 검토 후 계산용으로 등록합니다. 전 항목의 규정 해석과 자동계산 검증은 완료되지 않았습니다.

## 실행

압축을 풀고 `index.html`을 Edge 또는 Chrome으로 여세요. 외부 CDN이나 설치 과정 없이 프로젝트 안의 JavaScript를 사용합니다. 이 환경에서는 브라우저 실행이 차단되어 직접 파일 열기 호환성 및 화면 검증을 완료하지 못했습니다. 기관 브라우저가 로컬 파일 스크립트를 제한하면 GitHub Pages의 정적 배포를 사용하거나 승인된 로컬 정적 서버를 이용하세요.

개발용 Node.js 22 이상에서 다음 명령을 사용할 수 있습니다.

```powershell
node --test tests/*.test.cjs
node build.cjs
```

`dist`는 index.html, src, vendor만 복사합니다. 사용자 업무 파일과 저장한 프로젝트 JSON을 해당 폴더에 넣지 마세요. 실행 시 업무 데이터는 메모리에만 존재하며, 새로고침하면 사라집니다. 작업 JSON 저장 버튼으로 PC에 저장할 수 있습니다.

## 업무 순서

첫 화면은 **대시보드**이며, 메뉴는 **대시보드 → 공사정보 관리 → 공사비 산정** 순으로 시작합니다. 공사비 산정에서 공종·규격을 검색하고 수량, 단위당 재료 단가, 할증을 입력합니다. 원문 대조가 필요한 후보는 등록 화면에서 검토를 마치면 공사비 산정 화면으로 돌아옵니다. 저장한 공종과 경비는 복사·수정·삭제할 수 있습니다.

공통 할증은 2026 품셈 1-2-2의 14개 분류를 제공합니다. 공종 해설 계수 × (1 + 공통 품 할증률 합계) × (1 + 노임 할증률 합계)로 노무비를 계산합니다. 야간작업은 품 25%와 노임 50%를 함께 적용하며, 다른 공통 품 할증과는 품 할증끼리 합산합니다. 고소작업 높이·건물층수·왕복 이동시간은 입력값으로 산정하며, 범위가 정해진 할증은 요율과 적용 근거를 직접 입력합니다. 터널 사다리/고소작업, 전차선 차단/운전빈도·구내입환·사다리, 야간 노임 중복 등은 차단합니다. 공종별 해설의 미등록 조건은 근거와 적용 계수를 직접 입력할 수 있습니다. 일부 작업분만 해당되면 수량 행을 나누세요. 선택하지 않으면 할증 없이 저장됩니다.

1-1-6 재료 할증은 재료 수량만 증가시키고 시공수량과 노무비에는 반영하지 않습니다. 철거손실률은 신규 재료 할증과 다른 개념이므로 여기에 합산하지 않습니다. 공통 품의 적용 조건을 원문과 확인한 후 저장하며, 모든 현장 조건의 적용 여부를 자동 판정하지 않습니다.

**적용 기준 및 설정 → 제비율 적용표**의 **첨부 서식의 17개 항목 불러오기**는 2026.04.13. 건축공사 간접공사비 서식의 항목·산정 기준·유의사항을 불러옵니다. 요율은 비워 두며 사용자가 적용/제외를 선택하고 입력합니다. 요율 방식은 기준금액 × 요율 + 기초액(원), 금액 직접입력 방식은 최종 산정금액을 사용합니다. 관급 포함 안전관리비의 두 산식 비교, 공기(년)를 적용하는 이행보증수수료 등은 계산 근거와 최종 금액을 직접 입력합니다. 통신공사에 대한 별도 일반관리비 구분, 환경보전비 및 건설기계대여보증의 적용 제외를 확인하세요. 이 서식의 요율을 모든 통신공사에 자동 적용하지 않습니다. 적용표 저장 후 작업 JSON으로 보관합니다.

기계경비는 사용시간과 시간당 단가를 곱하고, 기타경비는 입력 금액을 합산합니다. 노임단가와 제비율을 등록한 뒤 **산정하기**를 누르면 원가계산서를 확인할 수 있습니다. **엑셀 저장**은 공사원가계산서, 산출내역서, 표준일위대가, 자재단가표, 노임단가표의 계산 시점 값을 담은 새 통합문서를 만듭니다. 편집을 이어갈 때는 작업 JSON을 사용합니다.

제공된 빈 설계내역서 양식으로 작성하는 순서는 다음과 같습니다. 기계·기타경비가 포함된 작업은 공사원가계산 화면의 **엑셀 저장**을 사용하세요.

1. 공사정보에서 공사명, 위치, 기준일, 연도, 기간, 종류, 발주기관을 입력합니다.
2. Excel 가져오기에서 제공된 빈 설계내역서 양식을 선택합니다. 원본 파일 자체는 프로그램 배포물에 포함되지 않습니다.
3. 노임단가 가져오기에서 같은 양식 또는 동일 구조의 파일을 선택합니다. 기본 가져오기 기간은 원본에 기재된 2026-01-01부터 2026-08-31입니다. 설정에서 실제 적용기간과 근거를 확인합니다. 현재 시점 공사에 그대로 적용하면 안 됩니다.
4. 품셈 검색에서 항목을 추가합니다. 수량산출에서 단위수량과 개수를 입력합니다. 길이가 없는 공종은 단위수량을 1로 두고 개수를 입력합니다. 포설과 성단은 각각 추가합니다.
5. 공종별 해설과 공통 할증을 확인합니다. 공사비 산정에서 선택한 할증의 근거·품 계수·노임 계수를 검토합니다. 변경 이력과 선택값은 작업 JSON에 포함됩니다. 행별 노임 할증을 사용하는 경우 기존 빈 양식 대신 공사원가계산 화면의 엑셀 저장을 사용합니다.
6. 자재를 직접 입력하거나 자재단가산출기초 시트에서 가져옵니다. 여러 셀의 탭 구분 붙여넣기를 지원합니다. 단가·수량 변경은 즉시 계산에 반영됩니다.
7. **노임·제비율 설정**에서 직종별 일 노임과 제비율을 직접 입력합니다. 제비율은 산정 기준 금액, 적용기간, 근거, 적용 여부를 지정합니다. 기존 빈내역서 양식에 내보낼 때는 출력 셀도 지정합니다. 공사금액·기간·종류·기관에 대한 법적 적용 요건은 담당자가 검토합니다. 검토 완료를 선택한 빈 목록은 모든 제비율 제외를 뜻합니다.
8. 일위대가와 공사원가를 확인한 후 Excel 파일을 저장합니다. 수식 변경 이력도 별도 저장합니다. Excel에서 링크 업데이트 여부를 검토한 다음 수량 변경 및 재계산을 확인합니다.

## 데이터 모델과 기준 연결

`src/catalog-data.js`는 전체 문서와 4,032개 계산 후보를 제공합니다. `src/reference`에는 원문 587쪽의 이미지가 있습니다. `src/standards.js`는 기존에 대조한 6개 계산항목을 기본 제공합니다. 원본 PDF의 인쇄면 90~92쪽, PDF 120~122쪽을 텍스트와 렌더링 이미지로 대조했습니다. UTP 구내 4P, RJ45 플러그, Modular Outlet, 2.2m 미만 랙, 24포트 패치패널, 패치패널 성단을 포함합니다. 원문 전체 해설의 기계적 판정을 구현한 것은 아니므로 적용 조건을 확인해야 합니다.

각 품셈은 id, code, name, spec, unit, baseQuantity, labor, year, version, source, page, verified, conditions, included, excluded, separate, revised, adjustments를 가집니다. labor는 직종별 base이며 adjustments는 id, name, factor, basis입니다. 기본 계수는 base입니다. 실제 자료 검증이 완료된 항목만 verified를 true로 설정합니다. 여러 조건의 동시 적용은 검증된 단일 조합 항목으로 사전에 구조화해야 합니다. 프로그램은 임의 계수 합산을 수행하지 않습니다.

노임단가 객체는 trade, price, from, to, source를 갖습니다. 적용일에 해당하는 동일 직종 자료가 0개 또는 2개 이상이면 계산을 막습니다. 자재 객체는 name, spec, unit, price, quantity, date, source, note를 가집니다.

제비율 객체 예시는 다음과 같습니다. 숫자는 등록 형식을 설명하는 0이며 공식 요율이 아닙니다.

```json
{"id":"indirect","name":"간접노무비","rate":0,"bases":["directLabor"],"from":"2026-01-01","to":"2026-12-31","source":"공식 자료명·조항·페이지","reviewed":false,"enabled":false,"cell":"D9"}
```

산정 기준 ID는 material, directLabor, expense와 앞서 등록한 항목 id입니다. expense는 입력한 기계경비와 기타경비의 합계입니다. 요율 계산은 나열 순서대로 수행합니다. 정액, 구간별 누진, 상한액, 역산을 사용하는 항목은 현재 엔진에서 지원하지 않습니다.

표준품셈·노임단가·제비율은 작업 JSON 또는 설정의 JSON 편집으로 등록할 수 있습니다. 다른 기준연도는 year/version과 적용기간을 함께 관리하세요. 자동 PDF 표 추출·검수 편집기와 범용 Excel 열 매핑은 후속 작업입니다.

## Excel 처리

자체 포함한 JSZip 3.x가 ZIP을 읽고 저장합니다. XML 읽기는 브라우저 DOMParser, 쓰기는 지정된 셀 노드 교체를 사용합니다. 전체 통합문서를 다른 객체 모델로 재작성하지 않습니다. 대상 셀 외의 XML 및 ZIP 구성요소는 보존합니다. 바뀐 수식의 캐시값을 제거하고 열기 시 전체 재계산을 요청합니다. 브라우저 자체에는 Excel 전체 수식 평가기가 없습니다.

제공 빈 양식 전용으로 재료비 9행, 직종 7행, 공종 19행을 지원합니다. 초과하면 내보내기를 중단합니다. UPS 전기공사 예시는 시트 구조를 조사했으며 정보통신공사 산정 기준으로 전용하지 않았습니다. 해당 양식의 자동작성과 실제 UPS 금액 대조는 미구현입니다.

원본에 포함된 외부 파일 관계 2개는 보존합니다. 앱에서 링크를 열거나 요청하지 않습니다. Excel이 별도로 링크 갱신을 요청할 수 있으므로 대상을 검토하세요. 매크로, 임베디드 개체, 전자서명 파일은 거부합니다. 배열·데이터표 수식의 직접 수정은 거부하고 공유 수식 기준 셀의 잔존 여부를 검사합니다.

집계표 A5와 자재단가산출기초 A2의 원본 #REF!를 수정합니다. 재료비·직종별 노무비에 원 단위 절사 또는 반올림을 적용합니다. 원가계산서의 기존 고정 제비율은 검토한 목록으로 교체하며, 제외 항목은 0으로 표시합니다. D26의 천원 단위 절사는 원 단위 합계로 바꿉니다. 기존 양식에 있던 법정 요율은 공식 기준으로 자동 채택하지 않습니다. 변경된 수식 및 이유는 JSON 이력으로 제공합니다.

## GitHub Pages

GitHub에 `ict-estimator` 저장소를 만들고 이 프로젝트의 소스만 main에 추가하세요. Settings → Pages → Source를 GitHub Actions로 선택합니다. 포함된 workflow가 자동 테스트, 정적 빌드, Pages 배포를 수행합니다. 모든 자산 경로가 상대경로이므로 저장소 하위 경로에서 실행됩니다.

저장소 계정이 지정되지 않아 이번 작업에서 실제 GitHub 게시 및 배포는 수행하지 않았습니다. Sites 별도 호스팅은 사용하지 않았습니다. 실제 배포 후 브라우저 Network 검증이 필요합니다.

## 남은 검증과 기능

전체 후보의 계산·조건 검증, 복잡한 행렬표와 산식의 자동 구조화, 제비율 법적 적용 자동 판정, 임의 XLSX 매핑, 대량 행 확장, 자동 PDF 추출 검수, 실제 UPS 설계와의 금액 검산을 추가해야 합니다. 공식 단가·제비율 원자료의 최신성은 검증되지 않았습니다. 브라우저 UI, 동적 네트워크, Microsoft Excel에서의 수량 수정 재계산은 현재 환경 제약으로 미검증입니다. 상세 결과는 SECURITY.md에 기록했습니다.


## 전체 품셈 검색과 계산 등록

공종 및 품셈 검색에서 번호·공종·규격·본문을 검색하고 장별로 좁힐 수 있습니다. 페이지당 40개 항목을 표시합니다. 전체 원문·부록 보기와 PDF 쪽 번호 입력으로 1~587쪽을 모두 열 수 있습니다. 본문 검색 결과에는 목차 밖의 부록도 포함됩니다. 이미지 선택 시 확대하며 인터넷 요청 없이 함께 배포한 정적 이미지를 표시합니다.

목차 항목 수에는 상위 분류, 공통기준, 삭제 항목 26개가 포함됩니다. 이를 계산 가능한 규격 수로 해석하지 마세요. 표 726개에는 부록과 설명용 표도 포함됩니다.

계산 후보 4,032개 중 2,464개는 표의 단위 열까지 추출했고, 1,568개는 단위와 기준수량을 원문에서 확인해 입력해야 합니다. 병합 셀의 물리적 위치로 항목명을 이어 붙이고 여러 줄의 숫자를 분리했습니다. 행렬형 표, 식으로 정의된 품은 원문을 검토해 별도 입력해야 합니다. 공통 할증은 공사비 산정 화면에서 조건을 직접 선택합니다.

후보의 원문 대조·등록 버튼으로 편집 화면을 엽니다. 규격, 수량 단위, 기준수량, 직종별 기본품, 적용 조건을 확인하고 확인란을 선택하면 계산용으로 등록됩니다. 확인 전에는 계산 엔진에서 적용을 거부합니다. 등록 후 수량에 추가하고 필요한 직종별 노임을 등록합니다. 자동 후보가 없는 항목도 원문에서 계산항목 등록 버튼으로 입력할 수 있습니다. 삭제 항목에는 등록 버튼이 없습니다.

등록에는 사용자 검토 상태, 검토 시각, 원본 PDF SHA-256, 원문 페이지와 표 위치를 남깁니다. 등록 결과는 작업 JSON에 저장되므로 다음 사용 시 해당 JSON을 열어야 합니다. 원본 이미지와 본문은 프로그램 안에 고정 데이터로 포함됩니다. 업무 공사명이나 수량은 이미지 경로에 포함되지 않습니다.

## 데이터 재생성

`tools`에 PDF 추출·병합셀 복원·목차 및 계산 후보 생성 스크립트를 포함했습니다. Python의 pdfplumber가 필요합니다. 이 스크립트는 제공된 2026판의 PDF 587쪽과 인쇄면 오프셋 30쪽을 대상으로 합니다. 다른 연도에는 페이지·목차 체계를 확인한 후 스크립트와 검증 기준을 수정해야 합니다.

```powershell
python tools/extract_catalog.py "공식품셈.pdf" "work/new-source-pages"
python tools/enrich_catalog.py "공식품셈.pdf" "work/new-source-pages"
python tools/build_catalog.py "공식품셈.pdf" "work/new-source-pages"
node --test tests/*.test.cjs
node build.cjs
```

PDF를 교체할 때는 새 캐시 폴더를 사용하세요. 이미지도 원본에서 1600픽셀 크기로 다시 렌더링한 뒤 `src/reference/page-001.webp`부터 같은 페이지 번호로 교체하고 대조해야 합니다. 기존 검증한 6항목의 자동 갱신은 수행하지 않습니다.

### GitHub 저장소에서 실행

GitHub 저장소는 원문 이미지를 `reference-bundle/`에 보관합니다. `node restore-reference.cjs`를 실행하면 각 파일의 SHA-256을 검증하고 `src/reference/`에 복원합니다. `npm test`, `npm run build`, Pages 워크플로에서도 복원합니다.
